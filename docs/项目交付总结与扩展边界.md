## 二、系统达成的关键非功能性与架构质量指标

1. **多租户数据强隔离**：
   - 所有数据库查询与更新均强制绑定机构租户；涉及主键资源访问、文件下载、批次查看时均拦截跨机构越权，测试用例 `testCrossOrgAccessDenied` 100% 覆盖。
2. **数据资产安全与隐私合规**：
   - 公民身份证号绝不以明文落库，采用 AES-128 对称密文存储；配合不可逆 SHA-256 索引确保等值高效检索；
   - 界面统一展示为脱敏格式（如 `110101********1234`）；
   - 导出文件下载端点实施路径规范化与文件名清理，杜绝目录穿越越权漏洞。
3. **高并发与数据强一致性**：
   - 选床占床与退住释放床位均在 `@Transactional` 事务内显式加持 `SELECT ... FOR UPDATE` 悲观锁，杜绝高并发重入抢占同一床位；
   - 财务收款严格依靠唯一约束 `uk_payment_idempotent` 实现接口防重幂等；
   - 财务流水严禁物理删除，只允许退款审批冲正冲销。
4. **高吞吐与内存保护**：
   - 异步报表导出采用游标流式分页拉取，边查边刷入磁盘，避免千万级大数据一次性加载爆破 JVM 堆内存；
   - 导出文件自动注入 UTF-8 BOM 编码，彻底解决 Windows Excel 中文乱码。

## 三、未实现能力与后续扩展边界声明

为遵循交付严谨性与诚实原则，现明确阐述本系统的能力边界及生产落地演进路线：

### 3.1 真实硬件与物联网协议边界
- **当前已实现**：设计了通用的 `IotProtocolAdapter` 接口，支持设备台账管理、绑定/解绑长者与空间、设备事件记录、以及通过 HTTP API 接收模拟网关上报的体征/在床遥测数据。
- **边界声明**：系统**未直接对接真实私有硬件厂商的闭源网关协议**（如私有串口透传、未公开的 Modbus/Zigbee 硬件专有协议）。在生产环境需要接入特定品牌雷达/床垫时，仅需实现 `IotProtocolAdapter` 并启动对应 MQTT/TCP Broker 监听进程，即可无缝落地。

### 3.2 政务专网与监管平台边界
- **当前已实现**：预置了民政长者、民政床位、卫健照护、应急安全 4 套权威模板；支持动态字段映射、字典转换；实现了针对 18 位公民身份证号格式、11 位手机号和必填项的逐行前置校验并精准定位错误；支持合规 CSV 打包并提供了 `RegulatorySubmissionAdapter` 扩展点。
- **边界声明**：在未经各属地民政局/卫健委真实政务专网前置机接口文档与 mTLS 客户端数字证书授权前，**系统不宣称已直连政务外网**。当前通过标准文件导出与受理回执单号登记完成合规交付与业务闭环。

### 3.3 商业第三方收单清算边界
- **当前已实现**：支持支付宝、微信、银行转账、现金等全渠道收款登记、账单核销、防重幂等号、金额精准计算与退款审批流。
- **边界声明**：系统未直接调用微信/支付宝商户平台的统一下单与对公退款银企直连 API。如需打通真实资金收单清算，只需在 `PaymentServiceImpl` 中接入微信支付/支付宝官方 SDK 的收银台回调即可。

## 四、运维与架构演进建议

1. **只读副本读写分离**：未来单机构在住长者突破上万人且报表频繁查询时，可配置 MyBatis-Plus 动态数据源实现主写从读。
2. **定时归档任务**：对于超过 1 年的设备高频遥测流水 (`iot_telemetry_data`)，建议配置 MySQL 按月分区或引入 InfluxDB / TDengine 进行时序数据冷热分层。
3. **文件集中对象存储**：当前流式导出文件暂存于本地沙箱 `exports/` 目录；后续上云部署可平滑替换为阿里云 OSS 或 MinIO 对象存储服务。
